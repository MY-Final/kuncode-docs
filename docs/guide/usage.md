# 配置成功之后：第一次怎么用

这一页讲的是**配置已经成功之后**怎么开始用 AI 编程工具。它不重复安装，也不重复配置 Base URL 和 API Key。

如果你还没配好，先看：

- [让 AI 安装并配置工具](/beginner/first-run)
- [准备 API Key](/guide/api-key)
- [选择接入方式](/guide/endpoints)

## 先建立正确预期

能聊天，不等于能写代码。

一个能用于编码的工具，至少要能完成三件事：**调用工具（tool call）、读取文件、执行命令**。只会回答问题的模型，可以当聊天助手，但很难真正帮你改代码。

所以第一次使用，建议按下面的顺序来：先对话 → 再读文件 → 再改代码 → 再跑测试。每一步都确认通过，再进入下一步。

## 第一次对话

先用最简单的问题，确认模型能正常回答：

```text
你好，请用一句话介绍你自己，并告诉我你现在是什么模型。
```

能正常回复，说明认证、协议入口和模型名都没问题。这一步只验证“能不能说话”，还不能说明它适合写代码。

## 让它读文件

先让 AI 读，不要让它改。把下面这段复制给它：

```text
请先不要修改任何代码。

请阅读项目根目录下的 README.md，然后用 5 句话总结：
1. 这个项目是做什么的
2. 用什么语言和技术栈
3. 怎么安装依赖
4. 怎么运行
5. 怎么跑测试

只做阅读和总结，不要改任何文件。
```

如果它真的读到了文件内容，而不是编造，说明读文件能力正常。

::: warning 先读再改
新手最容易犯的错，是一上来就让 AI “帮我改一下项目”。它可能在没看懂代码的情况下大改一通。

先让它读、让它解释，确认它理解的是你的真实项目，再让它动手。
:::

## 让它改代码

第一次改代码，只让它改**一个文件、一处最小改动**：

```text
请只修改 <文件路径> 这一个文件，完成下面这一处最小改动：
<用一两句话描述你要改什么>

要求：
1. 动手前先告诉我你准备改什么，等我确认。
2. 只改这一个文件，不要顺手重构、不要调整格式、不要动其他文件。
3. 改完后展示完整 diff，并解释每一处改动。
```

::: tip 一定要看 diff
改完不要只看它说“已完成”，一定要看 diff。重点确认：

- 是不是只改了你说的地方
- 有没有偷偷改别的文件
- 有没有顺手重命名、重构、升级依赖

发现改多了，直接让它撤销，重新来。
:::

## 让它跑测试

让 AI 执行测试，并把完整结果给你看：

```text
请运行这个项目的测试，并把完整输出贴给我。

如果有失败：
1. 先告诉我失败的是哪个测试、可能的原因是什么。
2. 不要直接改代码，先给出修复方案让我确认。
3. 我确认后再改，改完重新运行同一个测试。
```

::: warning 不要盲目接受“测试通过”
有些 AI 会跳过测试、只跑一部分，或者把失败说成成功。要求它贴出**完整输出**，自己看有没有 failed、error、skipped 之类的字样。
:::

## 每次改动后的三步

不管改得多小，都按这三步走：

1. **看 diff**：确认改动范围和你说的一致，没有多余改动。
2. **跑测试**：至少跑受影响的测试；有条件就跑全量测试。
3. **小步提交**：一次提交只包含一件事，提交信息写清楚改了什么、为什么改。

这三步能让 AI 的改动始终可控、可回滚。

## 怎么判断模型能不能用于编码

想确认一个模型或工具是否真的适合编码，依次验证三项：

| 验证项 | 怎么做 | 通过标准 |
| --- | --- | --- |
| tool call | 让它读一个文件 | 它调用了工具，而不是凭记忆回答 |
| 读文件 | 让它总结一个真实文件 | 总结内容和文件一致，没有编造 |
| 执行命令 | 让它运行一条只读命令，例如查看版本 | 它真的执行了命令，并贴出输出 |

三项都通过，才说明这个组合可以用于编码。只通过“对话”一项，说明它只能聊天。

## 常见失败信号

| 现象 | 通常意味着什么 | 下一步 |
| --- | --- | --- |
| 能聊天，但不能读文件 | 模型或协议入口不支持 tool call | 换一个支持 tool call 的模型，检查协议入口 |
| 能读文件，但不能改文件 | 工具处于只读或计划模式，或没有写权限 | 检查工具的权限/模式设置 |
| 能改文件，但不能跑命令 | 命令执行被关闭，或沙箱限制了执行 | 检查工具的沙箱和权限设置 |
| 工具调用直接报错 | 网关转换丢掉了 tool call 字段，或协议不兼容 | 对照协议入口和错误信息排查 |

具体错误码和排查步骤见[错误码与排障](/guide/errors)。如果是认证、地址、额度问题，也都可以在那里找到对应入口。
