# 准备 API Key

无论你用 Codex、Claude Code 还是 OpenCode，第一步都一样：**先创建一个 API Key，并记下服务地址**。

这一步只做一次。后面的工具教程都会直接引用这里。

## 1. 打开令牌页面

登录你的服务控制台，进入 **API 密钥** 页面，点击右上角的 **创建 API 密钥**。

## 2. 填写表单

![创建 API 密钥表单](/images/api-key/create-token.png)

字段不少，但大部分保持默认即可。真正要关注的是这几个：

| 字段 | 说明 | 建议 |
| --- | --- | --- |
| **名称** | 令牌标识，只用于你自己区分 | 按用途命名，例如 `codex-local` |
| **分组** | 决定走哪个上游渠道和倍率 | 不确定就用默认分组 |
| **过期时间** | 到期后令牌自动失效 | 选「永不过期」或按需设置 |
| **数量** | 一次创建几个令牌 | 通常填 `1` |
| **无限配额** | 是否限制这个令牌的花费 | 打开则跟随账户余额；关闭可设置上限 |

::: tip 建议按工具分别创建令牌
给 Codex、Claude Code 各建一个独立令牌，将来对账、排查、吊销都方便。
一个令牌多个工具共用虽然可以，但出问题时分不清是谁在用。
:::

填完点击右下角的 **保存更改**。

## 3. 复制密钥并记下服务地址

![在列表中复制密钥并查看 API 节点](/images/api-key/copy-key.png)

创建完成后回到列表，这里有两个信息要记住。

**① 复制密钥**

在 **API 密钥** 这一列，点密钥右侧的复制按钮。

::: warning 密钥只显示一次
多数服务在创建后不再回显完整密钥。请**立即**复制并保存到密码管理器。

如果丢了，只能删除后重新创建。
:::

**② 记下 API 节点**

列表上方的 **API 节点** 就是你的服务地址，例如 `https://kuncode.120403.xyz`。

这个地址在后面的配置里会反复用到，本教程中统一称作 **Base URL**。

::: tip 复制时不要带末尾斜杠
记录成 `https://kuncode.120403.xyz` 即可，不要写成 `https://kuncode.120403.xyz/`。
:::

## 4. 确认 Key 可用

在配置工具之前，先确认这个 Key 本身是通的：

```bash
curl https://kuncode.120403.xyz/v1/models \
  -H "Authorization: Bearer sk-xxxxxxxx"
```

把地址和密钥替换成你自己的。返回模型列表就说明 Key 没问题。

| 返回 | 含义 | 下一步 |
| --- | --- | --- |
| 模型列表 | Key 可用 | 继续看[选择接入方式](./endpoints) |
| `401 Unauthorized` | Key 错误、过期或被禁用 | 检查是否复制完整、是否已过期 |
| 余额或额度不足 | 账户额度不够 | 充值或调高令牌额度 |

## 进阶：权限收窄

如果在意安全，可以在创建令牌时展开 **高级设置**：

- **模型限制**：只允许这个令牌调用指定模型
- **IP 白名单**：只允许指定 IP 或网段使用，支持 CIDR

两者都是可选的。个人本地使用可以跳过，团队或 CI 场景建议开启。
