# 配置提示词库

这一页是**给 AI 的提示词**，不是给人执行的操作步骤。小白只需要复制、粘贴、回答 AI 的问题。

使用原则：

- 一次只让 AI 做一件事。
- 让它先检查、再执行、最后验证。
- 涉及 API Key 时，自己粘贴，不要发到聊天里。
- 改配置前要求它先备份。

## 1. 环境检查

```text
请检查这台电脑是否已经具备安装 AI 编程工具的条件。

请检查：
1. 操作系统和版本
2. Node.js 和 npm 是否存在，版本是多少
3. 包管理器（winget / brew / apt 等）
4. 网络是否能访问常用服务
5. 是否存在代理或公司网络限制

只做检查，不要安装或修改任何东西。
最后用一张表告诉我：已满足什么、缺少什么、建议先装什么。
```

## 2. 推荐工具

```text
我完全不懂命令行，想用 AI 编程工具。

我的情况：
- 系统：<Windows/macOS/Linux>
- 预算：<只想用免费 / 可以少量付费>
- 用途：<写代码 / 读代码 / 学习>

请根据我的情况推荐一个工具，优先考虑：
1. 安装最简单
2. 有免费或低成本方案
3. 社区活跃、文档清楚

只推荐一个，并说明理由。不要一次给我一堆选项。
```

## 3. 一键安装并配置

```text
请帮我在本机安装并配置 <工具名>。

要求：
1. 先检查前置条件，缺少什么就直接帮我装。
2. 实际执行安装命令，不要只给我命令。
3. 找到正确的配置文件位置。
4. 写入配置，并在修改前备份原文件。
5. API Key 让我自己粘贴，不要让我把完整密钥发给你。
6. 运行验证命令，确认模型能调用。
7. 最后告诉我：装了什么、改了哪些文件、怎么卸载。
```

## 4. 接入自定义服务

```text
请把 <工具名> 配置成使用我的自定义服务。

我的服务信息：
- API 节点：<地址>
- 协议入口：<不知道 / Chat Completions / Responses / Anthropic Messages>
- 模型 ID：<不知道 / 具体模型名>

要求：
1. 先根据工具文档判断 Base URL 应该带不带 /v1。
2. 先备份配置文件。
3. 只改必要的字段，不要重写整个文件。
4. 配置完成后用一个最小请求验证。
5. 如果失败，读取完整报错，判断是地址、认证、协议还是模型问题。
```

## 5. 配置免费模型

```text
我想用免费额度先跑通 AI 编程工具，不想马上付费。

请：
1. 列出当前可行、来源正规的免费方案。
2. 比较额度、模型、是否支持 tool call、速率限制。
3. 优先选择配置最简单的。
4. 确认方案后直接帮我配置。
5. 实际验证能否调用模型。
6. 告诉我免费额度的限制，以及什么时候需要换付费方案。

不要推荐共享 Key、来路不明的中转站或违反服务条款的方案。
```

## 6. 验证配置是否成功

```text
请验证 <工具名> 的配置是否真的可用。

请依次测试：
1. 工具能否启动，版本是多少
2. 当前读取的是哪个配置文件
3. 当前使用的 Base URL 和模型是什么
4. 能否列出可用模型
5. 能否完成一次最小对话
6. 能否读取一个本地文件

每一步都实际运行，不要只检查配置文件。
最后告诉我：哪一步通过、哪一步失败、失败原因是什么。
```

## 7. 排查配置失败

```text
我按你的步骤配置了 <工具名>，但是失败了。

完整报错：
<粘贴报错>

请：
1. 判断问题属于环境、安装、配置、认证、协议、模型还是额度。
2. 读取当前实际配置文件，不要凭猜测。
3. 一次只改一个变量，改完立刻验证。
4. 不要打印完整 API Key。
5. 如果无法确定，告诉我需要向服务商确认什么。
6. 最后说明根因和避免方法。
```

## 8. 切换模型

```text
请把 <工具名> 当前使用的模型从 <旧模型> 切换为 <新模型>。

要求：
1. 先确认新模型在服务端确实存在。
2. 确认新模型支持当前协议入口和 tool call。
3. 备份配置后再修改。
4. 改完实际调用一次验证。
5. 如果新模型不可用，自动回滚到旧模型并告诉我原因。
```

## 9. 修复工具调用失败

```text
我的 AI 编程工具能聊天，但不能读取文件或执行命令，提示工具调用失败。

请：
1. 检查当前模型是否支持 tool call。
2. 检查协议入口是否支持工具调用。
3. 检查是否有代理或网关转换丢掉了工具调用字段。
4. 用最小请求验证。
5. 给出修复方案；如果不支持，推荐一个支持 tool call 的模型。
```

## 10. 安全轮换 Key

```text
我怀疑 API Key 可能泄漏了。

请：
1. 告诉我应该在控制台执行哪些吊销和重建操作。
2. 帮我找到本机所有保存了旧 Key 的位置。
3. 更新配置文件和环境变量，但不要打印完整 Key。
4. 验证新 Key 可用。
5. 告诉我如何检查异常调用记录。
6. 提醒我清理 Git、日志、Shell 历史和截图中的泄漏源。
```

## 11. 回滚到官方配置

```text
请把 <工具名> 恢复成官方默认状态。

要求：
1. 先备份当前配置。
2. 移除自定义 Base URL 和 provider。
3. 清除本地保存的旧凭据，但不要打印内容。
4. 恢复官方登录方式。
5. 验证工具能正常启动。
6. 告诉我如何在控制台吊销不再使用的 Key。
```

## 12. 迁移到新电脑

```text
我要把这台电脑上的 AI 编程工具迁移到新电脑。

请：
1. 列出需要迁移的工具、配置文件和依赖。
2. 不要导出明文 API Key。
3. 在新电脑上重新安装工具和依赖。
4. 在新电脑上重新创建或填写 Key。
5. 逐项验证配置。
6. 告诉我旧电脑上应该清理什么。
```

## 怎么写自己的提示词

记住这个结构：

```text
背景：我的系统、工具、服务、现状
目标：我要达成什么
限制：不要做什么、安全要求
验证：怎么确认成功
```

对小白来说，最有用的一句话是：

```text
请直接帮我执行，不要只给我命令和教程。
```
