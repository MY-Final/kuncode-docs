# 配置失败怎么办

配置失败很正常，大多数问题都能修。这一页不要求你懂技术，只要求你按顺序做三件事：**把报错复制下来 → 先问帮你配置的 AI → 再按类型找对人**。

::: tip 先别慌
报错不等于你做错了。命令行、配置文件、API Key、网络代理任何一处有一点不对，都会报错。下面先按“失败发生在哪一步”分成四类，找到你属于哪一类，再往下走。
:::

## 先找到你属于哪一类

| 你的情况 | 通常表现 | 下一步 |
| --- | --- | --- |
| 还没装好 | 提示“命令找不到”“不是内部或外部命令”，或安装过程本身报错 | 看下面的“第三步”，回到对应的工具页重装 |
| 装好了但连不上 | 401、403、404、429、连接超时，提示 Key 或地址无效 | 先看“第二步”，再找你的 API 服务商 |
| 能聊天但不能读文件 / 改代码 | 能正常对话，但让它读文件、改代码、执行命令时没反应或报错 | 这是 tool call 问题，先看“第二步” |
| 用着用着出问题 | 之前能用，突然限流、超时、提示余额不足 | 先看“第二步”，多半要找服务商 |

> 说明：**tool call（工具调用）**指让 AI 真正去读你的文件、改代码、执行命令的能力。免费或某些模型不支持它，就只能聊天，不能帮你操作项目。

## 第一步：先别关窗口，把报错复制下来

**这一步最重要。** 大多数问题修不了，是因为只发了一句“打不开”，别人无从下手。

1. **不要关闭报错窗口。** 一旦关掉，报错可能就找不到了。
2. 找到终端或工具里**最后 20 行**内容，从下往上选中、复制。
3. 如果报错出现在图形界面里，直接**截图**，或复制界面里的错误文字。
4. 如果工具提示了**日志文件路径**，打开那个文件，复制最后 20 行。

复制时尽量保留这些信息，它们能帮别人快速定位：

- 完整的错误文字（不要只写“失败了”）
- HTTP 状态码（例如 401、404、429）
- 你当时用的工具名、模型名
- 出错的大致时间

::: warning 不要只发“打不开”
“打不开”“用不了”“报错了”这类描述无法定位问题。请至少附上最后 20 行报错，以及你用的是哪个工具、哪个模型。
:::

## 第二步：先问帮你配置的 AI

如果你是用 AI 帮你安装和配置的，**先问它**。它看过你的电脑，通常比任何人都更快定位问题。把下面整段复制给它，并把真实报错粘贴在最后：

```text
我按你之前的步骤配置 AI 编程工具，现在失败了。请帮我排查。

我遇到的报错是（已脱敏）：
<把最后 20 行报错粘贴到这里>

请按下面的要求做：
1. 先判断这属于哪一类问题：安装 / 认证 / 地址 / 额度 / 网络 / tool call。
2. 读取我真实的配置文件后再判断，不要凭猜测给建议。
3. 一次只改一个变量，改完让我验证，确认有效再改下一个。
4. 不要让我把完整的 API Key 打印到聊天里；需要检查 Key 时只看格式和前后几位。
5. 最后告诉我根本原因是什么，以及以后怎么避免。
```

如果 AI 改了几次仍然修不好，或者它明确说这是服务商或账号的问题，就继续往下走。

## 第三步：按类型找对人

不同的问题要找不同的地方，找错了只会耽误时间：

| 问题类型 | 找谁 | 怎么找 |
| --- | --- | --- |
| 安装、命令找不到、路径不对 | 本站对应工具页，或本站 GitHub Issues | 回到[工具接入](/tools/)里对应的工具页；如果是文档本身写错了，到[本站 Issues](https://github.com/MY-Final/kuncode-docs/issues)反馈 |
| Key、余额、限流、账号、分组 | **你的 API 服务商** | 登录服务商控制台，或联系服务商客服；本站无法帮你处理 |
| 工具本身的行为、界面、版本 | **该工具的作者或社区** | 到工具的官网、GitHub 仓库或用户社区提问 |
| 报错看不懂、不知道属于哪类 | 先问帮你配置的 AI | 见上面的“第二步” |

::: warning 本站能做什么、不能做什么
本站只提供接入指南和排障思路。**我们不能替你补 Key、充值、退款或查询账单**，也不能代替服务商做客服。涉及账号和费用的问题，只能找你的 API 服务商。
:::

## 发出去之前：一定要脱敏

把报错发到任何公开的地方（群聊、issue、截图）之前，先删掉下面这些内容：

- **完整的 API Key**（最重要，绝不能发）
- 账号邮箱、手机号
- 账单、余额、订单信息
- 内网地址、公司代理地址

**Key 怎么打码：** 只保留前 3 位和后 2 位，中间用 `...` 代替。例如 `sk-abc...xy`。

::: danger 任何情况下都不要把完整 Key 发到公开群、issue 或截图里
完整 Key 一旦泄漏，别人可以用它消耗你的额度。如果不小心发出去了，立刻去服务商控制台**吊销这个 Key**，再创建一个新的。
:::

## 可以直接复制的求助模板

### 发给 API 服务商

```text
你好，我在配置 <工具名>，遇到 <状态码>，报错是 <脱敏后的报错>。
我用的模型是 <模型名>，时间是 <时间>。
麻烦帮我确认 Key、余额、额度或分组是否正常。
完整 Key 我不会发出来，需要核对时我可以提供脱敏后的片段。
```

### 发到本站 GitHub Issues

```text
系统：<Windows 11 / macOS / Linux>
工具：<Codex / Claude Code / OpenCode / ...>
服务类型：<官方 API / 自建网关 / 第三方兼容服务>
复现步骤：
1. ...
2. ...
脱敏报错：
<粘贴最后 20 行，删掉 Key、账号、代理地址>
```

本站 Issues 地址：<https://github.com/MY-Final/kuncode-docs/issues>
